Point-cloud registration

Check good warm starts before the next scheduled checkpoint

Early interpolation enlarged the point cloud and made one older pipeline 5.8× slower. In a later matched POT comparison, earlier warm-start checks cut five complete registration runs by 12–35%.

What slowed down

In the early interpolation pipeline the 3,485-point scan grew to 13,499 representative sites in the first interpolation stage. Recovering three starting poses took 5.199 s instead of 0.892 s with the original method. This was a full alignment experiment, not the same fixture as the later POT timing study.

What changed mathematically

Registration repeatedly updates poses and then solves for correspondences. With the previous frame’s scalings as a warm start, the next plan can satisfy the requested marginal tolerance well before the stock solver checks again. The candidate evaluates the same marginal residual after updates 2, 3 and 4 as well as at the ordinary checkpoints. It returns early only after checking both marginals on the materialized matrix. No plan_tol is added.

Changing only the scheduling rule in the same implementation reduced those eight frames from 2.33 to 1.88 ms. Across all eight historically weak settings, seven paired timing intervals favored the candidate over stock. Five end-to-end runs of 56 frames took 12–35% less time. The eighth, which already converged in one update per frame, showed no clear difference.
