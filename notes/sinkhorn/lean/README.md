# Sinkhorn 0.2.0의 Lean 검증

## 이번에 확인한 결론

양의 확률질량 두 개, 유한한 실수 비용행렬, 양의 정규화 계수에서 시작한다. 조밀한 Sinkhorn 반복을 코드처럼 균일한 행 배율로 초기화한다. 추가 조기 종료 검사 두 개 중 실행한 검사가 통과하면, 그 시점에 반환하는 전체 수송행렬과 유일한 엔트로피 최적계획 사이의 총변동거리(TV)는 정확한 실수 연산에서 엄밀히 `stopThr/4`보다 작다. 어느 반복에서 검사하든 적용된다. 이 명제를 한 번에 읽으려면 [CertifiedExit.lean](CertifiedExit.lean)의 **ScalingAudit.certified_exit**를 보면 된다. Python 소스는 0.2.0 재현 묶음의 버전을 기준으로 대조했다.

## 실제 코드가 재는 두 오차

기호 $p,w$는 행·열 목표 질량, $K_{ij}=\exp(-M_{ij}/\varepsilon)$는 원래 커널이다. $0<l\le K_{ij}\le h$, $t=h/l$, $r=(t-1)/(t+1)$, $C_k=\min\{k-1,(1+t)/2\}$로 둔다. $R,S$는 행과 열의 개수다. 코드는 커널을 만들 때 최솟값과 최댓값을 구한다. `gibbs_stopping`은 유한 행렬에서 그 두 값이 실제 원소로 달성됨도 포함한다.

현재 행 배율이 $u$일 때 $v=w/(K^\top u)$로 열을 맞춘 뒤 $a=p/(Kv)$로 행을 맞춘다. 반환할 행렬은 두 검사 모두 $F_{ij}=a_iK_{ij}v_j$다. TV는 전체 원소별 절댓값 차이 합의 절반이다.

| 코드 위치 | 측정량 | 반환할 $F$와 최적계획 사이의 TV 상한 |
|---|---|---|
| 열이 많은 경우, 행 보정 전 | $e_0=\|u\odot(Kv)-p\|_1/2$ | $\min\{1+C_R,\ C_S r\}e_0$ |
| 그 밖의 경우, 행 보정 후 | $e_1=\|v\odot(K^\top a)-w\|_1/2$ | $C_S e_1$ |

`dense_checks`는 이 식에 코드와 같은 행렬·벡터 연산을 사용한다. `guard_factor`는 나눗셈을 피하는 조건분기와 $C_k$의 동치를, `reciprocal_rate`는 코드의 $l/h$ 식과 $r$의 동치를 검증한다. `certified_exit`은 분모를 $10^{-300}$ 이상으로 두는 경우도 포함한다. 코드가 빠른 경로에서 요구하는 열 수 2 이상과 일치한다. `tol`이 양수이면 검사에 쓰는 예산은 $\text{tol}/4$다.

## 이전 증명과 연결한 위치

| 단계 | 이전 상태 | 이번 증명 |
|---|---|---|
| 잔여분포의 다방향 판정, 혼합 오차 영역, 팔레트 위상차 | 기존 JointResidual 및 MixedRGB 선언과 공리 로그가 있음 | 기존 자료를 대조했다. 이 선언들은 새 검증 수에 포함되지 않는다. |
| 교차비에서 조건부 TV, 잔여 짝의 전파, 한 번의 보정, 기하급수 | ManyRows의 11개 선언으로 검증됨. 당시의 `limit_certificate`는 수렴과 단계별 조건을 인자로 받음 | 기존 파일을 그대로 가져와 `scaled_kernel_contraction`, `paired_transfer`, `diagonal_cross`, `correction_size`, `abs_sum_bound`를 필요한 곳에서 호출했다. |
| 행 수에 따른 $k-1$ 상한과 교차비 상한의 결합 | 이전 문서에서 전체 연결이 서면으로 남음 | `ordered_cut_bound`, `plan_certificate`. 같은 열합을 가진 두 양의 스케일링에서 행 배율에 따른 절단을 세어 유한 잔여 상한을 얻고, 교대 보정을 적용해 기하급수 잔여를 제거한다. |
| 실제 교대열의 수렴과 최적해의 식별 | 이전 수렴 정리가 가정하던 입력 | `alternating_limit`은 행과 열을 실제로 번갈아 갱신한 전체 라운드 열이 성분별로 수렴함을 증명한다. `closed_scalings`는 극한의 양성과 원래 커널의 배율 표현을 복원한다. `objective_gap`, `unique_minimum`, `optimal_scaling`, `gibbs_stopping`은 0인 원소를 포함한 비음수 경쟁 계획과 비교해 유일한 전역 최적해임을 보인다. |
| 잔여 질량의 위치를 이용한 보강 | 짝별 전달 보조정리만 검증됨 | `paired_certificate`가 근사 행합의 오차 $\alpha$와 행쌍별 상한을 전체 계획에 결합한다. 행쌍별 계수와 실제 잔여의 균형식은 명시적 입력이다. |
| 제곱거리 기하와 보간 요약 | 과거 보간 프로토타입의 일부 단계가 서면 증명 | `sq_cost_swap`, `squared_box_cross`가 좌표 너비부터 교차비까지 연결한다. `tensor_bound`는 좌표별 오차와 연산자의 안정성 상수에서 텐서 오차를 얻는다. `summary_tv`, `summary_plan`은 사건별 근사오차를 주변합 TV와 원본 계획 TV에 연결한다. |
| 라이브러리의 두 조기 종료, 균일 초기화 | 이전 수치 대조와 소스 주석 | `dense_checks`, `rowIter_pos`, `certified_exit`가 위의 두 식과 종료 보증을 연결한다. |
| 커널 재사용 | 0.2.0의 실행 테스트 | `dispatch_sound`, `trace_sound`는 캐시가 비어 있는 상태에서 시작한 임의 호출열을 다룬다. 후보 서명이 충돌하거나 입력값이 바뀌거나 저장을 건너뛰거나 캐시를 비워도 새 계산과 같은 값을 반환한다. `kernel_trace`는 이를 커널, 첫 열 곱, 두 계수에 적용한다. |

### 적용 조건과 남은 범위

- **실수 산술과 소프트웨어의 경계.** 실수 행렬과 정확한 양의 정규화 질량을 사용한다. Python에서 합이 1에 아주 가까운 입력을 허용하는 검사, 부동소수점 지수·반올림·언더플로, BLAS, NumPy의 쓰기 방지, 포인터 비교와 동시 메모리 변경은 이 Lean 증명의 대상에 포함되지 않는다. 따라서 실제 float64 출력에 대한 엄밀한 구간 오차 보증으로 읽을 수 없다.
- **종료 지점.** `certified_exit`의 예산은 추가 조기 종료 검사에 적용된다. POT의 정규 체크포인트는 주변합의 L2 기준으로 종료할 수 있다. 반복 한도 소진 시의 반환값, 원래 POT에 위임한 경로에도 같은 계획 TV 예산을 적용할 근거는 이번 정리에서 나오지 않는다.
- **캐시 가정.** 키에는 행렬의 전체 값·모양과 정규화 계수가 들어 있으며 호출 동안 값이 고정된다. 후보 서명은 어떤 함수여도 되고, 캐시를 쓰기로 결정할 때는 전체 키의 동등성을 사용한다. 캐시의 정확성은 순수한 값 모델에서 증명했다. 코드와 모델의 대조 지점은 `_auto_kernel`, `_same_cost`, `_build_kernel`이며 Python·C 실행 의미와의 기계 검증된 동치는 남아 있다.
- **과거 별도 보간 경로.** 고전적인 1차원 Chebyshev–Lobatto 오차와 Lebesgue 상수, RGB 혼합 Newton 나머지를 Cauchy 미분 상한과 결합하는 해석 단계, 부호 있는 요약의 Newton 최적화 구현 전체는 서면 근거로 남는다. `tensor_bound` 등은 어떤 단일 좌표 또는 국소 오차 추정을 입력받는지 정리문에 명시한다. 현재 0.2.0의 조밀한 조기 종료는 보간기를 호출하지 않는다.
- 성능 수치와 실제 이용 환경의 속도는 기존 측정 결과로 남겨 두었다.

## 재현

Lean 4.34.1, mathlib 커밋 `d13f23b723b8a846827a245b89c10fc7d3f11612`을 사용한다. 압축을 푼 폴더에서 다음을 실행한다. elan, git, Python 3가 필요하다.

```sh
lake exe cache get
bash verify.sh
```

`lake-manifest.json`이 의존성을 고정한다. 첫 실행 시 Lake가 패키지를 가져올 수 있다. `verify.sh`는 소스의 SHA-256을 확인한 뒤 빈 출력 폴더에서 이번 모듈을 검사한다. 기존 의존성 `ManyRows.lean`은 새 환경에서 한 번 컴파일한다. 이번 감사에서는 원본 해시를 확인한 그 의존성의 빌드 결과를 재사용했다. 새 모듈을 예전 빌드 디렉터리에서 찾는 경로는 검사에서 제외했다.

`Audit.lean`에 열거한 **40개 공개 선언**에는 연결 보조정리도 들어 있다. 각 선언에 대해 `#print axioms` 출력을 읽어 허용 목록과 비교하며, 경고를 오류로 처리한다. `logs/clean-build.log`, `logs/axioms.log`, `logs/source-check.log`가 이번 검사 기록이다. `evidence/`에는 이전 ManyRows 감사 로그와 소스 대조 해시를 넣었다.
